# 聊天媒体轮播

从 `use-media-carousel.ts` 开始读。它只连接数据、布局和位置控制；每次打开弹窗都是一个独立会话，关闭时一起卸载。

优先使用浏览器和库的公开能力：浏览器负责滚动和吸附，Virtual 负责虚拟化与分页锚定，Query 负责查询及缓存。组件只补充双视口同步和数据进入布局的时机，避免再实现一套滚动引擎。

| 模块                                         | 职责                                                           |
| -------------------------------------------- | -------------------------------------------------------------- |
| `use-media-pages.ts`                         | 查询前后页、保存已展示的数据、调度预取和失败重试               |
| `use-carousel-layout.ts`                     | 观察容器尺寸，计算固定宽度和两端留白                           |
| `use-fixed-carousel.ts`                      | 配置虚拟范围、固定尺寸缓存和库自带的插入锚定                   |
| `carousel-position.ts`                       | 消息内偏移与像素坐标之间的纯计算                               |
| `carousel-scroll-controller.ts`              | 保存消息 ID 与连续偏移，决定谁驱动滚动，恢复插入或缩放后的坐标 |
| `use-media-carousel-scroll-sync.ts`          | 将控制器连接到 React 生命周期、输入事件和两个视口              |
| `detail-carousel.tsx` / `thumb-carousel.tsx` | 渲染虚拟项和媒体内容                                           |
| `carousel-scroll-viewport.tsx`               | 视口样式、输入绑定和吸附开关                                   |

## 数据何时进入界面

查询结果与已展示数据分开保存。允许滚动中预取一页，但只有两条轮播都停止滚动后才发布新数据。在结果尚未发布时暂停继续预取，避免持续滚动导致后台加载完整聊天记录。

分页结果通过 React Query 的稳定 `select` 转成消息列表，转换缓存和相同数据的引用复用由库处理。停止滚动直接使用 Virtualizer 的 `isScrolling` 和默认防抖：浏览器回归中，原生 `scrollend` 会在小幅滚轮输入之间触发，过早发布新页。

同一个 InfiniteQuery 同时只发一个分页请求。两端都需要数据时先取前页；发布后重新判断另一端。加载失败停止自动重试，由界面提供重试按钮。

## 谁决定滚动位置

位置表示为 `{ messageKey, progress }`，`progress = 0` 表示视口与该消息居中，`0.25` 表示向右偏移四分之一张图。插入前页改变索引，缩放窗口改变像素宽度，都不改变消息身份。

用户最近操作的视口是滚动来源。控制器在两个方向都换算完整的连续位置，差异由 CSS 吸附决定：

- 大图就绪后始终启用 `x mandatory`，程序的 `instant` 滚动也由浏览器落到吸附位置。
- 缩略图仅在大图为滚动来源且其 `isScrolling` 为真时关闭吸附，逐位置跟随；大图停止后自动恢复 `x mandatory`。缩略图被用户操作时始终启用吸附。

控制器保存来源的连续位置，插入和缩放时据此恢复，不另行计算吸附位置。切换来源时，读取新来源实际的滚动位置接管，因为浏览器吸附后的落点可能与程序请求的位置不同。

按钮直接更新共同位置。只有滚动来源能更新共同位置，因此跟随视口的事件自然不会反向同步；无需记录或拦截程序滚动事件，也不读取虚拟库私有字段。

连续同步直接调用原生 `scrollTo({ behavior: "instant" })`。Virtualizer 的 `scrollToOffset` 会等待请求位置收敛，而吸附可能让小数位置永远不可达，这里不需要启动那套校正流程。

浏览器可能在尺寸测量更新前先触发重新吸附。此时忽略使用旧尺寸的滚动事件，等待布局提交后恢复共同位置。

## 维护约束

- 两条轨道的单元格均为固定宽度。图片解码不改变单元格几何，因此无需逐项 `measureElement`。
- 虚拟范围额外保留当前位置的消息，确保缩放或大跨度滚动时目标图片仍在 DOM 中，浏览器才能吸附到它；目标提交后再恢复坐标。
- Virtualizer 是可变实例。读取它的编排及视图保留 `use no memo`，避免 React Compiler 缓存旧的虚拟项或滚动状态。
- `useLayoutEffect` 负责布局提交后的坐标恢复；滚动事件负责用户产生的位置变化。
- 在 `apps/web` 运行 `pnpm test --run` 执行位置控制和分页回归用例。

涉及滚动时还应在浏览器验证：打开指定媒体、双向滚动与吸附、停止后恢复吸附并再次滚动、滚动期间分页返回、缩放、关闭重开，以及加载失败后重试。分页回归必须让请求在手势进行中返回。

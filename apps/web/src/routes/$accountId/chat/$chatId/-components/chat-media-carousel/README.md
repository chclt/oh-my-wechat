# 聊天媒体轮播

从 `use-media-carousel.ts` 开始读。它只连接数据、布局和位置控制；每次打开弹窗都是一个独立会话，关闭时一起卸载。

优先使用浏览器和库的公开能力：浏览器负责滚动和吸附，Virtual 负责虚拟化与分页锚定，Query 负责查询及缓存。组件只补充双视口同步和数据进入布局的时机，避免再实现一套滚动引擎。

| 模块                                         | 职责                                                       |
| -------------------------------------------- | ---------------------------------------------------------- |
| `use-media-pages.ts`                         | 查询前后页、保存已展示的数据、调度预取和失败重试           |
| `use-carousel-layout.ts`                     | 观察容器尺寸，计算固定宽度和两端留白                       |
| `use-fixed-carousel.ts`                      | 配置虚拟范围、固定尺寸缓存和库自带的插入锚定               |
| `carousel-position.ts`                       | 消息内偏移与像素坐标之间的纯计算                           |
| `carousel-scroll-controller.ts`              | 保存连续位置、读取实际位置，决定滚动来源并恢复布局后的坐标 |
| `use-media-carousel-scroll-sync.ts`          | 将控制器连接到 React 生命周期、输入事件和两个视口          |
| `detail-carousel.tsx` / `thumb-carousel.tsx` | 渲染虚拟项和媒体内容                                       |
| `carousel-scroll-viewport.tsx`               | 视口样式、输入绑定和吸附开关                               |

## 数据何时进入界面

查询结果与已展示数据分开保存。允许滚动中预取一页，但只有两条轮播都停止滚动后才发布新数据。在结果尚未发布时暂停继续预取，避免持续滚动导致后台加载完整聊天记录。

分页结果通过 React Query 的稳定 `select` 转成消息列表，转换缓存和相同数据的引用复用由库处理。停止滚动直接使用 Virtualizer 的 `isScrolling` 和默认防抖：浏览器回归中，原生 `scrollend` 会在小幅滚轮输入之间触发，过早发布新页。

同一个 InfiniteQuery 同时只发一个分页请求。两端都需要数据时先取前页；发布后重新判断另一端。加载失败停止自动重试，由界面提供重试按钮。

## 谁决定滚动位置

位置表示为 `{ messageKey, progress }`，`progress = 0` 表示视口与该消息居中，`0.25` 表示向右偏移四分之一张图。插入前页改变索引，缩放窗口改变像素宽度，都不改变消息身份。

用户最近操作的视口是滚动来源。来源只在控制器中保存，React 用 useSyncExternalStore 订阅同一个值，不另存 source 或用 effect 同步。控制器在两个方向都换算完整的连续位置，差异由 CSS 吸附决定：

- 大图就绪后始终启用 `x mandatory`，程序的 `instant` 滚动也由浏览器落到吸附位置。
- 缩略图仅在大图为滚动来源且其 `isScrolling` 为真时关闭吸附，逐位置跟随；大图停止后自动恢复 `x mandatory`。缩略图被用户操作时始终启用吸附。

控制器保存来源的连续位置，插入和缩放时据此恢复，不另行计算吸附位置。切换来源时，读取新来源实际的滚动位置接管，因为浏览器吸附后的落点可能与程序请求的位置不同。

控制器通过同一套坐标换算提供连续位置的 messageKey 和大图实际位置的 currentKey。同步 Hook 在同一次滚动或布局处理中更新详情的 currentKey，并通知外层关闭目标；不再经由组件渲染后的 effect 转发。详情没有居中项时 currentKey 为空，外层保留最后一个有效目标；关闭期间固定目标，不再跟随隐藏详情的位置更新。Virtual 的范围通知不覆盖每次中心换图，因此 currentKey 仍需由实际滚动事件更新。

按钮直接更新共同位置。只有滚动来源能更新共同位置，因此跟随视口的事件自然不会反向同步；无需记录或拦截程序滚动事件，也不读取虚拟库私有字段。

大图视口自身获得焦点时，左右方向键阻止浏览器默认滚动，复用上一张／下一张按钮的即时翻页。详情内部控件保留各自的键盘行为；缩略图视口继续使用原生键盘滚动。

连续同步直接调用原生 `scrollTo({ behavior: "instant" })`。Virtualizer 的 `scrollToOffset` 会等待请求位置收敛，而吸附可能让小数位置永远不可达，这里不需要启动那套校正流程。

浏览器可能在尺寸测量更新前先触发重新吸附。此时忽略使用旧尺寸的滚动事件，等待布局提交后恢复共同位置。

## 维护约束

- 两条轨道的单元格均为固定宽度。图片解码不改变单元格几何，因此无需逐项 `measureElement`。
- 虚拟范围额外保留当前位置的消息，确保缩放或大跨度滚动时目标图片仍在 DOM 中，浏览器才能吸附到它；目标提交后再恢复坐标。
- Virtualizer 是可变实例。读取它的编排及视图保留 `use no memo`，避免 React Compiler 缓存旧的虚拟项或滚动状态。
- `useLayoutEffect` 负责布局提交后的坐标恢复；滚动事件负责用户产生的位置变化。
- 在 `apps/web` 运行 `pnpm test --run` 执行位置控制用例。保留跨布局的位置语义和跟随不回写的检查；不模拟 React effects 手动执行 Hook。

涉及滚动时还应在浏览器验证：打开指定媒体、双向滚动与吸附、停止后恢复吸附并再次滚动、滚动期间分页返回、缩放、关闭重开，以及加载失败后重试。分页回归必须让请求在手势进行中返回。

## 打开关闭的过渡接入

ViewTransition 持有每对端点的几何运动；轮播持有媒体数据、浏览会话和布局。外部打开仍改变同一份受控状态。浏览会话保留到图片过渡或普通 Popup 淡出结束，挂载条件直接读取 ViewTransition 状态和 Base UI 的 open / hidden，不另存挂载状态或通过完成回调清空数据。open 与 transitionStatus 分别同步，不能用 ending 阶段推断内容仍挂载，否则会在关闭开始时短暂卸载并重置虚拟列表。消息触发器的打开接口只随会话保留/释放更新，不跟随各个动画阶段或当前媒体。

`DetailCarouselPreview` 和 `MessageListPreview` 提供两侧虚拟坐标；`MediaCarouselPreviewHost` 负责宽裁剪层及定位锚点。Preview 始终使用虚拟位置，不另存淡出锚点。详情 Preview 读取虚拟库的测量列表，不依赖当前渲染范围。

Provider 用 useId 给本轮播的容器加唯一前缀，Preview 在 DOM 提交后按目标 key 查找容器，无需注册表或额外渲染。仅打开过程提供大图估算；关闭过程使用真实聊天目标。缺少来源或终点时 ViewTransition 报告 skipped，轮播改用普通 Dialog 淡入淡出。

关闭时，已有图片过渡优先反向衔接。没有图片过渡时，通过 ref 读取滚动控制器的只读 `isDetailSnapped`：复用实际位置的 `progress` 和现有像素容差判断大图是否居中，不以 Virtualizer 的 `isScrolling` 判断，避免分页锚定引发的程序滚动误禁用图片过渡。位于两张图片之间时，通过 `Root.disabled` 改由 Popup 和 Backdrop 整体淡出。判断随关闭状态固定，不因之后吸附而补播；状态在读取时派生，不另存 React state 或增加滚动监听。

`media-carousel-layout` 同时提供 CSS 变量和 contain 估算。详情与 Preview 覆盖完整弹窗，图片通过 padding 避让绝对定位的缩略图。CSS 保留打开时的 Backdrop 淡入；普通 Dialog 显隐时 Backdrop 与 Popup 一起渐变，图片过渡关闭时 Backdrop 立即透明。图片过渡期间 Preview 祖先没有透明度或缩放过渡，控件独立淡出。

`readMediaPreview` 统一提取就绪图片的资源与固有尺寸。同一运动反向保留完整快照；没有来源时跳过图片过渡，不再从迟到的终点补取快照。文件的解析与释放沿用原有机制，不在轮播中增加资源注册表或引用计数。浏览到不同媒体时清空上一个媒体的备用快照。
